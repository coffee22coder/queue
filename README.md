# Брокер очередей (HTTP)

In-memory брокер: несколько независимых очередей, имя очереди — сегмент пути URL.  
Один бинарный файл, только стандартная библиотека Go.

## Запуск

```bash
go run main.go <port>
```

Пример:

```bash
go run main.go 8080
```

Сервис слушает `http://127.0.0.1:<port>/`.

---

## Модель

- Очередь называется как path: `/pet`, `/role`, `/anything`.
- Внутри каждой очереди сообщения отдаются **FIFO** (первым пришёл — первым ушёл).
- Очереди **не пересекаются**: `/pet` и `/role` — разные буферы.

---

## API

### PUT `/{queue}?v={message}`

Положить строку `message` в очередь `{queue}`.

| Ответ | Условие |
|-------|---------|
| **200**, пустое тело | Успех |
| **400**, пустое тело | Нет query-параметра `v` или он пустой |

```bash
curl -XPUT "http://127.0.0.1:8080/pet?v=cat"
curl -XPUT "http://127.0.0.1:8080/pet?v=dog"
curl -XPUT "http://127.0.0.1:8080/role?v=manager"
curl -XPUT "http://127.0.0.1:8080/role?v=executive"
```

---

### GET `/{queue}`

Забрать одно сообщение из очереди (FIFO).

| Ответ | Условие |
|-------|---------|
| **200**, тело = текст сообщения | В буфере было сообщение |
| **404**, пустое тело | Буфер пуст, параметра `timeout` нет |

После примеров PUT выше:

```bash
curl http://127.0.0.1:8080/pet    # cat
curl http://127.0.0.1:8080/pet    # dog
curl http://127.0.0.1:8080/pet    # 404
curl http://127.0.0.1:8080/role   # manager
curl http://127.0.0.1:8080/role   # executive
curl http://127.0.0.1:8080/role   # 404
```

---

### GET `/{queue}?timeout=N`

То же, что GET, но если буфер **пуст**, запрос **ждёт** до `N` секунд, пока не придёт PUT в эту очередь.

| Ответ | Условие |
|-------|---------|
| **200**, тело = сообщение | Сообщение появилось (уже было или пришло пока ждали) |
| **404**, пустое тело | За `N` секунд сообщения не было |
| **400**, пустое тело | `timeout` не число или `< 0` |

`N` — целое число **секунд**. `timeout=0` — не ждать (сразу 404, если буфер пуст).

```bash
# Терминал 1: ждём до 10 секунд
curl "http://127.0.0.1:8080/pet?timeout=10"

# Терминал 2: кладём сообщение — первый GET получит его и вернёт 200
curl -XPUT "http://127.0.0.1:8080/pet?v=bird"
```

**Порядок среди ожидающих GET:** если два клиента ждут с `timeout` на одной очереди, **первое** сообщение получает тот, кто **раньше** отправил GET (очередь ожидания FIFO, как у сообщений).

## Как устроено внутри (кратко)

Компонент **`Broker`** хранит map: имя очереди → состояние очереди.

Для каждой очереди два механизма:

1. **`messages []string`** — буфер для обычного GET (нет ожидания).
2. **`waiters`** — список GET-запросов, которые сейчас ждут с `timeout` (каждый со своим каналом).

**PUT:**

- Если есть ожидающие GET — сообщение уходит **первому** waiter (не в буфер).
- Если ожидающих нет — сообщение добавляется в конец `messages`.
- Если waiter уже «ушёл» по таймауту — сообщение кладётся в `messages`, чтобы не потерять.

**GET без timeout:** взять из начала `messages` или 404.

**GET с timeout:** если в `messages` уже есть данные — отдать сразу; иначе встать в `waiters` и ждать либо сообщение, либо истечение `N` секунд → 404.

Синхронизация — один `sync.Mutex` на брокер.
