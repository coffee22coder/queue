# Задание: брокер очередей (HTTP)

Реализовать брокер очередей в виде веб-сервиса.

---

## 1. PUT `/{queue}?v=message`

Положить сообщение `message` в очередь с именем `queue` (имя очереди может быть любым).

**Примеры:**

```bash
curl -XPUT http://127.0.0.1/pet?v=cat
curl -XPUT http://127.0.0.1/pet?v=dog
curl -XPUT http://127.0.0.1/role?v=manager
curl -XPUT http://127.0.0.1/role?v=executive
```

| Результат |
|-----------|
| Пустое тело + статус **200** (OK) |
| При отсутствии параметра `v` — пустое тело + статус **400** (Bad Request) |

---

## 2. GET `/{queue}`

Забрать (по принципу **FIFO**) из очереди с названием `queue` сообщение и вернуть в теле HTTP-запроса.

**Пример** (после PUT выше):

```bash
curl http://127.0.0.1/pet    # cat
curl http://127.0.0.1/pet    # dog
curl http://127.0.0.1/pet    # пустое тело + 404
curl http://127.0.0.1/pet    # пустое тело + 404
curl http://127.0.0.1/role   # manager
curl http://127.0.0.1/role   # executive
curl http://127.0.0.1/role   # пустое тело + 404
```

### Параметр `timeout`

Для GET-запросов должна быть возможность задать аргумент `timeout`:

```bash
curl http://127.0.0.1/pet?timeout=N
```

- `N` — количество **секунд**.
- Если в очереди нет готового сообщения, получатель должен ждать либо до момента прихода сообщения, либо до истечения таймаута.
- Если сообщение так и не появилось — **404**.

**Порядок получателей:** если два получателя ждут сообщения (используют таймаут), то первое сообщение должен получить тот, кто **первый** отправил запрос.

## Порт

Порт, на котором слушает сервис, задаётся **аргументом командной строки**.

---

## Ограничения

- Запрещено пользоваться сторонними пакетами — только **стандартная библиотека** Go.
- Задача в написании кода, а не в использовании чужих решений.

---

## Пожелания (не обязательны, но желательны)

- Весь код в **одном** `.go`-файле (ориентир — не больше ~200 строк).
- Не требуются README, `cmd/`, `internal/` и т.п. для сдачи.
- **Лаконичность:** не нужна гибкость больше, чем требует задача.
- **Без логов** работы процесса (только обработка ошибок), без дебага.
- Чем меньше кода — тем лучше.

---

## Критерии оценки

1. **Корректность** — условия выполняются.
2. **Архитектура** — нет лишних действий, только решающие задачу.
3. **Лаконичность и понятность** кода для других разработчиков.
